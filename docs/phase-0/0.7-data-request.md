## 1. Purpose

This is the single data request for Phase 1. It is issued in Week 1 because MI lead time is 3–4 weeks and the baseline (G1, Week 7) depends on it. Items are prioritised: P1 is on the critical path; P2 improves the baseline; P3 is useful in Phase 2.

Period: **1 November 2025 – 31 October 2026** (12 months) unless stated.

## 2. Handling

- Customer-identifying fields pseudonymised at source (customer number → hash). Partner does not need names.
- Corporate segment records: supplied to Bank BA only; partner receives aggregates (SD-02).
- Delivery via Bank secure file transfer to the project SharePoint; no email.
- Data retained for the engagement only; deleted at closure.

## 4. Data quality checks on receipt

| Check | Threshold | Action if failed |
|---|---|---|
| Deal count in DR-01 vs RFP figure (30,561) | ± 5% | Reconcile with MI before use |
| Stage history completeness (DR-02): share of deals with full stage path | ≥ 85% | Report baseline on complete subset; flag in G1 |
| Timestamp sanity (exited ≥ entered; no future dates) | 100% after cleansing | Exclude and report |
| Join rate DR-01 ↔ DR-02 ↔ DR-03 | ≥ 95% | Investigate key mismatch |
| FAL events (DR-08) coverage | Known; may be low | If < 50%, supplement with RM mailbox sampling in walk-the-process |

## 6. Activity survey (not an MI item; owned by WS3)

- Population: DR-11 users, sampled 15–20% stratified by role and segment (c. 150)
- Instrument: daily 15-minute self-report of time by activity category (c. 20 categories aligned to L2 taxonomy), Mon–Fri Week 5
- Anonymised; reported at role × segment level only
- Supplemented by time-and-motion on the five highest-volume activities (observed, not self-reported), Weeks 5–6

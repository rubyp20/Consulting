1. Structure and conventions

LevelWhatCountSource
EpicA shared component, pattern, exception path, rules capability, interface or data theme142.2
StoryA unit of behaviour the platform must provide, expressed as “As a [role], I need [capability] so that [outcome]”, with acceptance criteria≈ 952.3 steps and DDRs; 2.4 rule sets
RuleA decision table in the rules catalogue, referenced by stories, maintained as data14 (RS-01 to RS-14)2.4
Non-functionalAudit, access, performance, reporting, migration constraints§71.8; RFP §7; 2.5

Priority (Release 1)

MoSCoWMeaning here
MustRelease 1 cannot deliver the pattern without it; or a protected field depends on it
ShouldRelease 1 target; a stated fallback exists if it slips (fallback named on the story)
CouldRelease 2 candidate; design accommodates its absence

Conventions

  • Story IDs: component / pattern prefix + number (SC1-03, P2-02, EXB-01, RUL-05, INT-02, DAT-04, NFR-07).
  • “Platform” means the replacement system. “Rule” means a decision table from §4, evaluated with evidence written back (NFR-01).
  • Acceptance criteria are testable; where they reference a threshold, the rules catalogue holds the value and the story holds the behaviour.
  • Fit-gap column is populated by 2.7; blank at v0.7.

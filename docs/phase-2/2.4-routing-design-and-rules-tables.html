How to read the thresholds. Every numeric threshold below is a proposal chosen to be defensible and to be tested against the Phase 1 cohort data. Credit Risk Policy sets the actual values. The project’s contribution is the structure of each rule, the data it runs on, the evidence it records, and the sizing of each threshold’s effect (section 7), so that the trade-off between eligibility and risk is explicit when the values are set.

1. Approach

1.1 Rules as data, not workflow

Each rule set is specified as a decision table: a list of conditions on named data elements, and the outcome when the conditions hold. The platform evaluates the table at the step named in 2.3; the outcome and the rule version are written to the deal as evidence (DP-02). Rules are owned by the function named on each table and changed through that function’s governance, not by a system change. This is the mechanism by which deal type stops defining a workflow: the type is simply a condition column.

ElementMeaning
Rule set (RS-nn)A decision table with a single purpose, an owner, a version and an effective date
ConditionA test on a data element the platform holds at the evaluation point (1.8 field groups); every condition names its source
OutcomeRoute, required item, template, gate, limit or approver
Hit policyHow multiple matching rows resolve: First (ordered; first match wins), Any (all matching rows must agree), Collect (union of outcomes, e.g. required items)
EvidenceWhat is written to the deal: rule set, version, row(s) matched, input values at evaluation
OverrideWhether a human may override the outcome, by whom, and with what recorded reason

1.3 Design constraints applied

  • An early-warning flag (RS-11) always forces R-FULL or P5; no fast route is available to a flagged connection (DP-08).
  • A fast route never removes the authority control (C5); it changes who holds the authority and what evidence is recorded (DP-03).
  • Every fast route is sampled by Credit after approval at a rate set in CE-001 / CE-003, with a feedback loop to the thresholds.
  • Rules run on data captured at source; where a condition needs data the platform does not hold, the rule is marked Gap for 2.7 and the condition is conservative until the data exists.
